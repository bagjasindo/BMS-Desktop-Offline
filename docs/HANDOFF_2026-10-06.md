## Titik terakhir
Fondasi aplikasi Windows Desktop .NET 8 WinForms + PostgreSQL lokal/LAN/Wi-Fi telah dibuat.
Internet tidak diperlukan untuk operasional lokal. Arsitektur: PC Server PostgreSQL -> router/AP lokal -> PC/Laptop client BMS Desktop.
Belum boleh disebut PASS/release-ready karena belum dilakukan build Windows nyata, migrasi database kosong end-to-end, uji transaksi antar-role, backup/restore, dan uji multi-PC.

## Yang sudah dibangun
- Project .NET 8 WinForms, konfigurasi PostgreSQL/Npgsql.
- Login, PBKDF2 password hashing, bootstrap ADMIN tanpa password default.
- Role dasar: ADMIN, PRODUKSI, PPL, LOGISTIK, MARKETING, KEUANGAN, OWNER, PELANGGAN.
- Authorization foundation + assignment user ke kandang.
- Master perusahaan, kandang, partner, item, rekening perusahaan.
- Production cycle MITRA/MANDIRI + kontrak dan harga kontrak.
- Logistics: PO, penerimaan barang, stock movement.
- Produksi/PPL: Chick-In, Day 1 H+1, recording, BW, OVK, feed usage, ABK, extra sapronak.
- Marketing: panen dan Tambah Daging.
- Finance foundation: invoice/payment/allocation, BOP Produksi, Perawatan Kandang, BOP Kantor/Luar Kantor, supplier debt split, kasbon, payroll, cash ledger.
- Expedisi: Finance dana jalan -> Logistik menyelesaikan trip yang sama.
- Form Pengajuan Kas: 1 form -> banyak kelompok -> banyak rincian; berdiri sendiri dan tidak auto-post ke transaksi realisasi.
- RHPP foundation: mortalitas, BW, FCR, IP, contract BW price, biaya EXTRA/ABK/BOP, Tambah Daging.
- CLOSED protection dan immutable RHPP/closing snapshot.
- Backup metadata + pg_dump foundation, SHA-256 verification.
- CSV/export foundation, format Indonesia, nomor dokumen concurrency-safe.
- Migration runner, network health, transaction guard, row-version/concurrency foundation.
- Audit append-only.
- SOP deployment Wi-Fi/LAN, test plan, role matrix, business rules.

## Aturan bisnis yang wajib dipertahankan
- Chick-In mengaktifkan kandang/cycle.
- DOC received = populasi awal; Mati Box/DOA terpisah.
- Recording Day 1 = H+1.
- CLOSED historical memakai final snapshot dan tidak boleh dimutasi.
- Harga performa RHPP memakai kontrak, bukan harga beli Logistik.
- Tambah Daging: RHPP memakai harga BW kontrak; hutang/biaya supplier memakai harga aktual.
- Extra sapronak/feed dan biaya perusahaan di luar kontrak dikurangkan setelah RHPP kontrak.
- Perawatan/Renovasi Kandang terpisah dari BOP Produksi/RHPP dan mengurangi Global P&L.
- Form Pengajuan Kas hanya dokumen administrasi; tidak terhubung otomatis ke BOP, kasbon, arus kas, hutang, RHPP, laba/rugi atau realisasi.
- Data tidak tersedia ditampilkan '-' dan tidak boleh dibuat data palsu/0 seolah data nyata.
- Dashboard global read-only; Finance dapat melihat Global P&L.
- Hutang supplier dipisah MITRA/MANDIRI.
- Owner restore-only untuk backup/restore sesuai aturan terkunci.
- UI restriction saja tidak cukup; service/database authorization harus diperkuat.

## Catatan teknis penting untuk audit berikutnya
- Periksa mapping PostgreSQL date DateOnly/DateTime di ProductionService; AgeCalculator sudah dibuat tetapi integrasi perlu diverifikasi.
- CashRequestV2 adalah struktur final; service lama CashRequestService perlu dinilai/deprecate agar tidak ada dua jalur.
- RHPP calculation saat ini masih foundation, bukan formula final tervalidasi.
- Extra feed saat ini perlu audit nilai biaya karena quantity saja tidak cukup untuk biaya tanpa unit price/contract mapping.
- Supplier debt query/payment allocation perlu diuji agar agregasi tidak menggandakan nilai.
- CLOSED guard perlu diaudit untuk semua tabel yang terkait cycle.
- First-admin bootstrap, migration ordering, SQL idempotency dan transaction behavior harus diuji nyata.
- MainForm masih shell; modul UI belum lengkap.
- Belum ada hasil dotnet build/Windows runtime test.
